# Senecio channel-operator pipeline

Reproducible analysis pipeline for estimating the **channel operator**
**S = G<sup>1/2</sup> H G<sup>1/2</sup>** across eight *Senecio lautus* populations,
accompanying:

> Ortiz-Barrientos D, James ME, Burrage K. "The Geometric Snowball of Speciation."

This pipeline is the *Senecio* companion to the *C. elegans* pipeline at
`manuscript/analysis/celegans_pipeline/`. Both test the same theoretical
prediction — that hybrid fitness loss scales with the angle between the
population-specific genetic channels — against two independent empirical
systems.

---

## What the pipeline does

### Theoretical target

In the geometric-snowball framework, each population evolves a preferred
direction of additive genetic response — its **genetic channel** — determined
jointly by:

- **G**, the additive genetic variance–covariance matrix (heritable variation
  available to selection), and
- **H**, the fitness curvature matrix (the local shape of the adaptive
  landscape).

The channel operator **S = G<sup>1/2</sup> H G<sup>1/2</sup>** captures the interaction of the
two. When populations adapt to different environments, H differs between them,
and so their channels rotate apart. The angle between channels predicts hybrid
fitness loss via

> I<sub>geom</sub> ≈ k · θ<sup>2</sup>

when angles are small. Estimating S directly moves the empirical test from
*"does g<sub>max</sub> alignment predict RI?"* to *"does full channel misalignment
predict RI?"* — a much stronger test.

### Empirical realisation in *Senecio lautus*

Eight populations across four ecotypes:

| Ecotype   | Populations | Habitat              |
|-----------|-------------|----------------------|
| Dune      | D1, D3      | Coastal sand dunes   |
| Headland  | H1, H2      | Coastal rocky heads  |
| Tableland | T1, T9      | Alpine grasslands    |
| Woodland  | W2, W4      | Subtropical woodland |

Two trait blocks:

- **Vegetative (4 traits, direct):** Height, MSL_W, SB, MSD
- **Leaf (2 axes from PCA on 6 raw traits):** LeafPC1, LeafPC2 derived from
  Area, P2A2, Circularity, Nindents.Peri, IndentWidth, IndentDepth

### Two-stage workflow

| Stage | Script | What it does | Runtime |
|-------|--------|--------------|---------|
| **1** | `scripts/01_fit_G/population_G_D_snowball_analysis.R` | Fits population-specific G matrices via MCMCglmm paternal half-sib design. Computes pairwise D from common-garden means. Builds pairwise G geometry. | Hours (full MCMC); ~5 min (quick test) |
| **2** | `scripts/02_channel_operator/senecio_channel_operator_analysis.R` | Fits Lande–Arnold selection gradients (β, γ) per population × environment. Constructs H from γ. Computes S = G<sup>1/2</sup> H G<sup>1/2</sup>. Cross-validates with soil-based rank-1 H proxy. | ~2 min |
| **3** | `scripts/03_figures/make_figures.py` | Produces a summary figure and formatted tables from Stage 1 and 2 outputs. | Seconds |

## Quick start

```bash
# One-time: install R packages
Rscript requirements.R

# Test run (short MCMC, ~5 minutes total)
bash run_pipeline.sh --quick-test

# Full run (hours — MCMCglmm with 2.1M iterations × 8 populations × 2 blocks)
bash run_pipeline.sh

# Run only one stage (useful when iterating)
bash run_pipeline.sh --stage 2
```

Outputs land in:

```
data/processed/population_G_D_results/      Stage 1 outputs (~40 CSVs + RDS)
data/processed/channel_operator_results/    Stage 2 outputs (~7 CSVs + RDS)
results/figures/                            Stage 3 PDF figures
results/tables/                             Stage 3 formatted tables
```

Compare your numbers against `docs/expected_outputs.md` to confirm the run
matches the validated reference.

## Methodological choices — what each stage actually does

### Stage 1: population-specific G and pairwise D

Reads `Data_Exp1_Dmatrix.csv` (one row per plant, common-garden phenotypes)
and `Data_Exp2_Gvariance.csv` (one row per offspring, full-sib breeding
design).

For each of the eight populations, the script fits a multivariate
sire-dam-dam:sire breeding-design model in **MCMCglmm**:

```
cbind(traits) ~ trait - 1,
random = ~us(trait):sire + us(trait):dam + us(trait):sire:dam,
rcov   = ~us(trait):units
```

The additive genetic covariance matrix is extracted as **G = 4 × sire
covariance** (standard paternal half-sib scaling).

Two blocks are fitted separately:

- 4 × 4 **vegetative G** for (Height, MSL_W, SB, MSD)
- 2 × 2 **leaf G** for (LeafPC1, LeafPC2) after projecting onto an
  Exp1-derived PCA basis

Traits are scaled within population before fitting (`scale_within_population_for_G = TRUE`),
which focuses the analysis on **matrix shape and anisotropy** rather than
raw-scale variance magnitude.

Pairwise **D** is built from Exp1 population means as
**D<sub>ij</sub> = (μ<sub>i</sub> - μ<sub>j</sub>)(μ<sub>i</sub> - μ<sub>j</sub>)<sup>T</sup>**,
so each pairwise D is rank 1 by construction and its leading eigenvector is the
standardised divergence vector.

MCMC settings:

| Mode | NITT | Burnin | Thin | Saved samples | Runtime per G fit |
|------|------|--------|------|---------------|-------------------|
| Full (default) | 2 100 000 | 100 000 | 2 000 | 1 000 | ~10–30 min |
| Quick test | 260 000 | 60 000 | 200 | 1 000 | ~30–60 s |

Stage 1 produces per-population posterior-mean G matrices, pairwise G
geometry (g<sub>max</sub> angle, g<sub>2</sub> angle, leading-plane principal
angles), and D-to-G alignment summaries. See the Outputs section below for the
full file list.

### Stage 2: channel operator

Reads Stage 1 outputs plus field-transplant fitness data (Walter et al.) and
soil chemistry.

**Route A — Lande–Arnold selection gradients.** For each (population ×
environment × block), the script:

1. Links glasshouse morphology to field fitness via shared full-sibling
   family IDs.
2. Computes family-mean trait values and family-mean fitness (L10 =
   establishment by default; Bud or GE also supported).
3. Runs the standard Lande–Arnold quadratic regression:

   ```
   W_rel ~ z + z²  terms + cross-products
   ```

   yielding directional gradients **β** and quadratic gradients **γ**.
4. Constructs **H = −γ** (sign convention: stabilising selection → positive
   definite H). If γ is not negative-definite (so H would be indefinite), the
   script projects to the nearest positive-definite matrix via eigenvalue
   clipping.
5. Computes **S = G<sup>1/2</sup> H G<sup>1/2</sup>**, extracts its leading
   eigenvector in the whitened basis, and measures pairwise channel angles
   between Dune and Headland populations in shared environments.

**Route B — Soil-based rank-1 H proxy.** Independent cross-validation. Three
biologically meaningful soil axes (Salinity, Nutrients, Acidity) are built
from log-transformed, scaled PCA on subsets of the soil data. The local
trait–environment regression gives a divergence direction, and a rank-1
**H<sub>soil</sub> = d d<sup>T</sup>** is constructed per (population ×
environment). The same S computation is then repeated.

The **agreement between Route A and Route B** is the empirical test: if
channel angles are a real geometric feature (rather than regression artefact),
both routes should rank population pairs similarly.

### Stage 3: figures and tables

Thin Python layer that reads the CSV outputs of Stages 1 and 2 and produces:

- A summary figure showing G-matrix anisotropy, pairwise g<sub>max</sub>
  angles, and Lande–Arnold β gradients across all populations × environments.
- A formatted results table summarising channel angles and anisotropy.

These are the assets that get cited in the paper; they are derived, not
canonical. If you edit the figures you do so downstream of the pipeline.

## How to interpret the key numbers

**From `vegetative_G_summary.csv`:**

- `lambda1_over_lambda2` > 3 → strongly anisotropic G (one direction dominates)
- `leading_plane_prop` > 0.85 → most variance in the top two axes (reasonable
  for applying 2D channel geometry)

**From `pairwise_G_geometry_leafPC.csv`:**

- `gmax_angle_deg` = angle between the leading eigenvectors of the two G
  matrices. Small angles (< 20°) → concordant axes of genetic variation;
  large angles (> 60°) → axes point elsewhere.

**From `S_channel_angles_LA.csv`:**

- `S_channel_angle_deg` = angle between **whitened leading eigenvectors** of S.
  This is the full-curvature channel angle — what the geometric-snowball
  framework predicts should scale with hybrid fitness loss.
- Compare against `gmax_angle_deg` from Stage 1: the **delta** between the
  two is the selection-curvature contribution beyond what G-alignment alone
  captures (the Schluter-limit residual).

## Running on your own data

To adapt this pipeline to a different species, you would need to:

1. Replace `Data_Exp1_Dmatrix.csv` with common-garden phenotype data that
   includes `Ecotype`, `Population`, and the relevant traits.
2. Replace `Data_Exp2_Gvariance.csv` with breeding-design offspring data that
   includes `Block`, `Type`, `sire`, `dam`, and the same trait columns.
3. Replace `Walter_Data_Exp2.csv` with field-fitness data whose `Family`
   column matches the family IDs in the breeding design.
4. Adjust the trait blocks (`veg_traits`, `leaf_traits`) at the top of the
   Stage 1 script.
5. Re-run. Stage 1 and Stage 2 will fail early with clear messages if column
   names don't match.

## Troubleshooting

**`git: 'lfs' is not a git command`**
Git LFS is a separate install on macOS:

```bash
brew install git-lfs
git lfs install
```

**MCMCglmm install fails**

```r
# Order matters — coda first
install.packages(c("coda", "Matrix"))
install.packages("MCMCglmm")
```

On fresh macOS installs, `Matrix` may need a compiler toolchain. If
`install.packages` fails, install Xcode command-line tools first:

```bash
xcode-select --install
```

**Stage 1 takes too long**
Use `--quick-test` to confirm everything works, then switch to full run. For
the full run, you can set `save_model_objects <- FALSE` (default) to avoid
writing large fitted-model RDS files.

**Stage 2 stops with "Path configuration error"**
Stage 2 depends on Stage 1 outputs. Confirm
`data/processed/population_G_D_results/leaf_PCA_loadings.csv` exists before
running Stage 2. If not, run Stage 1 first:

```bash
bash run_pipeline.sh --stage 1
```

**Different numbers than the reference**
MCMCglmm uses random initial values. With full-run settings (≥ 1 000 saved
samples after thinning and burn-in), posterior means should agree with the
reference in `docs/expected_outputs.md` to ~3 significant figures for
eigenvalue ratios and to within a few degrees for principal angles. If you see
larger drift, check the diagnostics CSVs — low effective sample size or high
lag-1 autocorrelation will explain it.

## Relationship to the original `scripts/gmatricesDH/`

The two R scripts in this pipeline are **verbatim copies** of the validated
scripts at `scripts/gmatricesDH/` in the main `geometric-snowball` repository,
with one narrow exception: the **first few path lines** in each script have
been rewritten to use the pipeline layout (`data/raw/`, `data/processed/`)
rather than the original mixed layout. Those edits are clearly flagged by
comment blocks in the scripts. All analysis code — function definitions,
MCMC settings, statistical procedures — is identical.

This preserves the numerical validation already performed on the original
scripts while producing a clean reproducible shell.
