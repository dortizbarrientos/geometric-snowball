01

Why GitHub?

Every researcher recognises this:

thesis_final.docx
thesis_final_v2.docx
thesis_final_ACTUAL_final.docx
thesis_final_mark_comments.docx
thesis_final_mark_comments_revised.docx
thesis_SUBMIT_THIS_ONE.docx  ← which one is it?

Version control replaces this. Git is the tool. GitHub is the platform.

Complete history

Every change ever made, with who made it, when, and why.

Undo anything

Go back to any previous state of any file at any point in time.

Safe collaboration

Multiple people editing without overwriting each other's work.

Proof of priority

Timestamped commits establish when ideas were first developed.

02

Four core concepts

Repository

Your project folder, tracked by git. Contains all files and their complete history.

Commit

A saved snapshot. Every commit has a timestamp, author, and message. Return to any commit.

Remote

A copy of the repo on another server. origin = GitHub. overleaf = Overleaf.

Branch

A parallel version for experiments or major revisions. Merge back to main when done.

Untracked  → git doesn't know about it yet
Modified   → git knows it, and it has changed
Staged     → ready to commit  (after git add)
Committed  → safely saved in history
03

Setup pipeline

Do this once per project.

1
Create repo on GitHub

Go to github.com/new. Name it (e.g. additive-channels), set Private, add README, choose the TeX .gitignore template.

2
Clone to your computer 
git clone https://github.com/USERNAME/REPO.git
cd REPO
3
Create folder structure 
mkdir -p manuscript/figures manuscript/mathematica notes
4
Copy files in and commit 
git add .
git status   # always check before committing
git commit -m "Initial commit: manuscript, SI, figures"
git push origin main
5
Link to Overleaf 
git remote add overleaf https://git@git.overleaf.com/PROJECT_ID
git pull overleaf master --allow-unrelated-histories -X theirs
git push origin main

Your project ID is in the Overleaf URL: overleaf.com/project/69c719...

04

Daily workflow

Run these at the end of every writing session. Three commands is all it takes.

git pull overleaf master       # get latest from Overleaf
git add .
git commit -m "Describe what changed"
git push origin main           # archive to GitHub

Writing good commit messages

A good message completes the sentence: "If applied, this commit will…"

✓ Good
"Revise Discussion paragraph 2"
"Fix bib key CooperMessina2023"
"Update Fig 4 caption and SI S6"
"Revise abstract after reviewers"
✗ Bad
"update"
"fix"
"changes"
"asdfgh"

06

Branches & Tags

Branches for revisions

git checkout -b revision-round-1
# ... edit, commit ...
git checkout main
git merge revision-round-1
git push origin main

Good names: revision-round-1  ·  submitted-version  ·  accepted-version

Tags for milestones

git tag -a v1.0 -m "bioRxiv submission"  &&  git push origin v1.0
git tag -a v1.1 -m "PNAS submission"     &&  git push origin v1.1
git tag -a v2.0 -m "Accepted"            &&  git push origin v2.0

08

What to track and what to ignore

✓ Always track

  • .tex source files
  • .bib bibliography files
  • .py figure scripts
  • .R analysis scripts
  • .md documentation
  • Figure PDFs in figures/

✗ Never track

  • Compiled .pdf documents
  • LaTeX artefacts (.aux .log .bbl)
  • Large data files
  • Personal paths or tokens
  • .DS_Store (macOS)
  • __pycache__ / *.pyc
# .gitignore for a LaTeX + Python project
*.aux *.log *.bbl *.blg *.out *.synctex.gz
*.pdf
!manuscript/figures/*.pdf
__pycache__/ *.pyc

Troubleshooting

COMMONUpdates were rejected (fetch first)
git pull origin main --rebase
git push origin main
CONFLICTMerge conflict in manuscript

Open the file, find the <<<<<<< markers, keep the correct version, delete the markers.

git add . && git commit -m "Resolve conflict"
UNDOCommitted something wrong
git reset --soft HEAD~1  # undo last commit, keep changes
git revert HEAD           # or: new commit that reverses it
HISTORYNeed old version of one file
git log --oneline manuscript/main.tex
git checkout ABC1234 -- manuscript/main.tex
